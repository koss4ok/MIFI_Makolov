# «ЗОЖ» — наложение жизненного цикла управления проектом на фазы разработки

## 1) Конкурентный анализ и требования к продукту

### Конкуренты (минимум 3)

| Приложение | Что сильного | Чего обычно не хватает/где есть риски для MVP «ЗОЖ» |
|---|---|---|
| **MyFitnessPal** | Огромная БД продуктов, дневник питания, калории/макросы, зрелые решения для пользовательского опыта | Для MVP тяжело повторить объем контента и качество данных; высокие требования к поддержке и поиску |
| **Lifesum** | Красивые экраны, удобный ввод, понятные рекомендации | Сложнее отталкиваться от их глубины рекомендаций (дольше сроки); многие функции завязаны на регулярную обновляемость |
| **Yazio** | Системы питания, трекинг, диеты/планы, удобные витрины | Насыщенность фичами: для выхода в AppStore быстрее нужен “узкий” MVP без сложных интеграций |

### Требования к продукту

#### Функциональные
1. **Калькулятор калорий**: ввод параметров пользователя и расчет суточной нормы (и/или целевого значения) + отображение результата.
2. **Калькулятор воды (опционально)**: ввод/трекер потребления воды.
3. **Список полезных продуктов**: каталог продуктов (минимум: название + базовые нутриенты/ккал) + поиск/фильтрация по ключевым словам.
4. **Список диетических блюд (меню)**: список блюд (минимум: название + состав/ккал + привязка к продуктам из каталога).
5. **Персональный план тренировок**: формирование плана под цели пользователя (минимум: недельная структура + список упражнений по дням).
6. **Экран профиля/настроек**: параметры для расчета калорий и персонализации плана (возраст, рост, вес, пол, цель).
7. **MVP-логика сохранения состояния**: сохранение введенных параметров (и выбранных данных) между сессиями.
8. **Упаковка для AppStore**: подготовка карточки приложения (скриншоты/описание) + соблюдение требований магазина.

#### Нефункциональные
1. **Качество и стабильность**: отсутствие критических падений, воспроизводимый интерфейс, корректная обработка ошибок ввода.
2. **Производительность**: быстрые экраны каталогов/списков (использование пагинации/кэша для большого списка).
3. **Приватность и соответствие политикам**: корректная формулировка политики/лицензий (юридически).
4. **Локализация**: русский интерфейс как минимум для ключевых экранов.
5. **Инструменты управления качеством**: чек-листы релиза, тестовые сценарии.

## 3) Декомпозиция эпиков до задач и продуктовый бэклог

Правило приоритетов:
- **Важно**: без этого MVP 1.0 не выходит или критично для даты/успеха.
- **Средне**: повышает ценность, но можно отложить без срыва.
- **Неважно**: только если остается время; либо “плюшки” (например, социальная функция «Поделиться»).
